# Первый offline прототип FQI

Реализовано обучение Q-функции на подготовленных переходах и переносимый Python runtime для проверки решений по JSON-модели. Подключение JVM и первый технический замкнутый прогон описаны [отдельно](jvm-policy.md); эффективность и совместное управление обоими ресурсами пока не подтверждены. Артефакт явно помечается `deploymentAllowed: false`.

Метод основан на [Fitted Q Iteration](https://jmlr.org/papers/v6/ernst05a.html). Регрессор — [ExtraTreesRegressor из scikit-learn 1.6.1](https://scikit-learn.org/1.6/modules/generated/sklearn.ensemble.ExtraTreesRegressor.html). Выбор и ограничения исследовательской постановки приведены в [спецификации](learning-spec.md).

## Обучение

Используется Python 3.9–3.12 с зафиксированными зависимостями. CI использует Python 3.11. Пример настройки отдельного окружения:

```bash
python3 -m venv /tmp/iasr-ml-env
/tmp/iasr-ml-env/bin/python -m pip install -r docs/benchmark/tools/requirements-ml.txt
/tmp/iasr-ml-env/bin/python docs/benchmark/tools/train_fqi.py /tmp/iasr-prepared --out /tmp/iasr-fqi-model --iterations 8 --trees 32 --depth 6 --leaf 3 --seed 42
```

Вход должен быть получен `prepare_dataset.py`. Проверяются группы, эпизоды, идентичности примеров, сдвиг истории, фактические действия и маски. Данные из изменённого рабочего дерева отклоняются. Отсутствие в train роста/сжатия пула или совместных действий также останавливает обучение. Выходной каталог должен быть новым.

На каждой итерации обучается новый ансамбль:

```
target = observed_reward + 0.95 ** elapsed_seconds × max Q_previous(next_state, supported_next_action)
```

`Q_0=0` — инициализация итераций, а не утверждение о завершении физической системы. Если нет поддержанного продолжения, переход исключается с причиной `unsupported_continuation`; ему не присваивается искусственная нулевая будущая ценность. Аналогично исключаются неподдержанное наблюдённое действие и отсутствующее вознаграждение.

Число итераций задаётся заранее и фиксируется в отчёте. Validation используется для диагностических показателей; автоматический подбор итерации или гиперпараметров по нему в первом прототипе не реализован. Test оценивается после последней итерации и не участвует в подборе. Для дальнейшего исследования параметры можно выбирать отдельными запусками по validation, сохраняя test закрытым до окончательного выбора.

## Признаки и защита от утечек

Из четырёх окон берутся сигналы, перечисленные в спецификации, относительные и абсолютные размеры ресурсов, cooldown, фаза пула и измеренная длительность окна. Абсолютный номер тика, сценарий, UUID, повтор и будущий результат в текущие признаки не входят. Наблюдаемые размеры ресурсов до действия не заменяются желаемыми значениями.

Rref — 95-й процентиль положительного goodput последних окон train, не меньше 1. Показатели задержки делятся на SLO, goodput — на Rref, очереди и занятость — на соответствующий текущий ресурс. Ресурсы представлены относительно диапазона и фиксированных масштабов 100/32. Cooldown нормируется своим настроенным пределом, фаза пула — периодом. Длительность делится на номинальное окно.

Затем для каждого признака по текущим историям train вычисляются медиана и межквартильный размах с нижним пределом 0.1. Пропуск получает медиану, то есть ноль после центрирования, и отдельный двоичный индикатор. Если весь столбец отсутствует, используются центр 0 и масштаб 1. Ни следующие окна, ни validation/test не меняют эти статистики. Два признака действия добавляются после преобразования истории.

Вознаграждение соответствует исходной спецификации: полезная пропускная способность, штраф превышения p95, отказов, ошибок и изменения ресурсов. Это скалярный критерий обучения; итоговую эффективность надо оценивать также по исходным показателям отдельно. Нулевой goodput с отказами остаётся отрицательным сигналом; окно без каких-либо исходов не становится свидетельством выполнения SLO.

## Эмпирическая поддержка действий

Сначала применяется та же маска допустимости, что при сборе. После неё действие допускается только при наличии в соответствующей грубой области train не менее трёх наблюдений и двух эпизодов. Дополнительно требуется близкий пример этого действия из train: среднее квадратичное расстояние по нормированным признакам не больше 2.0. Эти значения — параметры первого прототипа, а не доказанная безопасная граница.

В поддержку не попадают validation/test. Отсутствие допустимого поддержанного действия даёт `action: null` и `fallback: true`; JVM-контроллер выполняет baseline. Наличие соседа и совпадение грубой области не исключают частичную ненаблюдаемость и ошибку Q-функции.

Поддержка и пригодные для Bellman-обучения переходы согласуются до фиксированной точки: после исключения переходов поддержка перестраивается по оставшимся, пока состав не перестанет меняться. Поэтому переход с неизвестным продолжением не может сам подтверждать наличие обучающей поддержки. Если фильтрация удаляет все переходы, требуется расширить данные, а не обойти проверку.

## Артефакты и проверка

- `model.json` — деревья, преобразования, порядок признаков, поддержка действий, веса вознаграждения, параметры обучения, версии библиотек, Git-версия тренера и SHA-256 входных файлов;
- `report.json` — диагностические ошибки по итерациям, число использованных/исключённых примеров, причины исключений и ошибка переносимого экспорта;
- `prediction-fixtures.json` — примеры численных входов и эталонных предсказаний для проверки JVM runtime.

Экспортируются численные массивы узлов деревьев, без pickle. Входы приводятся к float32 до сравнения с порогами, как при sklearn predict. Проверяется совпадение JSON runtime со sklearn на обучающих входах с допуском `1e-10`. Число потоков равно 1, seed фиксирован. Одинаковый код, зависимости и вход дают воспроизводимые преобразования и деревья; поле происхождения изменится при другой версии исходников.

Посмотреть предложения политики на наблюдённых историях:

```bash
python3 docs/benchmark/tools/fqi_runtime.py /tmp/iasr-fqi-model/model.json /tmp/iasr-prepared/test.jsonl
```

Такой просмотр не моделирует последствия предложенного действия. Bellman RMSE — условная диагностика на примерах, прошедших фильтр поддержки, а не оценка полезной пропускной способности новой политики. Маленькая ошибка, ненулевое число предложений и успешная сериализация не доказывают улучшение управления. Подключение через `Controller` и guardrails выполнено; для вывода об эффективности нужны новые независимые сравнительные эксперименты с повторами и абляциями.

Первый сохранённый [результат обучения](../benchmark/models/fqi-prototype-2026-11-08/README.md) содержит модель, численные проверки, происхождение данных и ограничивающий результат: ансамбль пока не выделяет влияние действия над пулом.

Последующий [аудит совместного покрытия](joint-data-iteration.md) добавил проверку действий после фильтрации: рост и уменьшение пула и хотя бы одно одновременное изменение обоих ресурсов должны остаться в реально обучающей выборке. Это необходимый минимум, а не достаточность покрытия. Старый диагностический экспорт теперь требует явного `--allow-incomplete-joint-support`.

`prepare_dataset.py --development-only --validation-scenarios spike` и `train_fqi.py --development-only` позволяют разрабатывать модель на train/validation без открытия test. [Вторая модель](../benchmark/models/fqi-balanced-pilot-2026-11-08/README.md) впервые использует действие пула на части train, но не меняет пул на validation и в техническом замкнутом прогоне; улучшение управления не установлено.
