# Сравнение pooled и Q по совместным действиям

Модели обучены на чистом `3c64f21` по [протоколу до обучения](../../../dissertation/action-conditioned-fqi.md). Данные неизменны: train 455 / validation 120; после фильтра поддержки 415 / 106 пригодных переходов. Test не открыт. Преобразования, поддержка и SHA всех входов совпадают между моделями. Контрольный pooled также сохранил прежние деревья reference из итерации retained-train.

| Вариант | Версия JSON | Общая структура | Train Bellman RMSE | Validation Bellman RMSE |
|---|---:|---|---:|---:|
| pooled / reference | 1 | 32 общих дерева | 0.607947 | 1.214411 |
| per-action / experimental | 2 | 7 лесов × 32 дерева | 0.803612 | 1.464599 |

Для обоих: 8 итераций, depth 6, min leaf 3, max features 1.0, seed 42, gamma 0.95 за секунду, n_jobs 1; поддержка 3 примера / 2 эпизода / RMS 2.0. Число параметров различается; это проверка представления Q, не сравнение при равном размере модели. Bellman RMSE нового варианта выше; по этому результату улучшение не заявляется и победитель не выбирается.

Отдельные регрессоры обучены для наблюдавшихся совместных нормализованных действий:

| Действие | Переходов |
|---|---:|
| −L, −P | 4 |
| −L, hold P | 121 |
| −L, +P | 6 |
| hold L, −P | 16 |
| hold | 218 |
| hold L, +P | 23 |
| +L, hold P | 27 |

Для `−L,−P` недостаточно примеров для двух листьев при min leaf 3: оценка остаётся константной. Редкие действия имеют высокую неопределённость; разные регрессоры могут отражать различия наблюдавшихся состояний и шум, а не причинные последствия действий.

На validation pooled предлагает hold 104, уменьшить лимит 3, увеличить пул 6; fallback 7. Per-action предлагает hold 58, уменьшить лимит 34, увеличить пул 11, совместно уменьшить лимит / увеличить пул 8, увеличить лимит 2; fallback 7. При фиксированном изменении лимита различия Q между поддержанными действиями пула имеются в 22 сравнимых validation-историях у per-action и в 6 у pooled. Это наблюдаемая чувствительность и предложения на чужих траекториях, не доказательство качества политики.

Оба обучения повторены побайтово (`model.json`, `report.json`, `prediction-fixtures.json`). Обе модели прошли по 13 JVM-тестов на 74 историях: точное совпадение float32-признаков и маски, поддержки, выбора и Q с допуском `1e-12`; отдельно 16 sklearn golden inputs. Goldens версии 2 покрывают все семь обученных действий. JSON-экспорт совпал со sklearn с максимальным расхождением 0.0 на проверенных входах. Сохранены оба артефакта, аудиты и журналы.

`protocol.json` фиксирует экспериментальный и контрольный варианты без выбора по Bellman RMSE. [План контура](technical-check-plan.json) соответствует порядку и условиям, зафиксированным до обучения. Модели остаются `deploymentAllowed: false`. Итоги контура сохраняются отдельно и не меняют параметры этой попытки.

В [контурной проверке](../../raw/action-conditioned-control-2026-11-08/README.md) per-action модель впервые выполнила изменения обоих ресурсов: 30 изменений лимита и 12 пула, включая 2 совместных. Все 158 решений двух моделей и 6 support fallback совпали с Python. Pooled только удерживал ресурсы. На spike у нового варианта лучше наблюдавшиеся goodput и p95, но на steady p95 хуже; один повтор на известных условиях не доказывает эффективности. Техническая возможность применения обученной совместной Q-политики подтверждена; независимое сравнение и абляции ещё необходимы.

Подготовка данных — [в описании retained train](../../../dissertation/retained-train-iteration.md); запуск тренеров — [в протоколе этой попытки](../../../dissertation/action-conditioned-fqi.md). Для точного повторения артефактов нужен checkout `3c64f21` и зависимости из моделей. `comparison.json` сохраняет входные SHA, диагностику и размеры моделей, `verification.json` — результат переноса.
