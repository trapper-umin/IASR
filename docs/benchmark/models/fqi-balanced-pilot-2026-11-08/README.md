Development-модель обучена на [новом пилоте](../../raw/balanced-pilot-2026-11-08/README.md). Тренер и данные — чистый commit `8972740750c4eb9d8b9cf679acb932bba539db84`. Два последовательных запуска дали побайтово одинаковые `model.json`, `report.json`, `prediction-fixtures.json`. Java-объект сбора использовал чистый `980ab8e`; версии разделены в provenance.

Параметры первой попытки были зафиксированы до сбора: 8 итераций, 32 ExtraTrees, глубина 6, min leaf 3, seed 42, gamma 0.95; поддержка 3 примера / 2 эпизода / RMS 2.0. Преобразования — только train. Модель сохраняет `deploymentAllowed: false` и `testEvaluated: false`.

В validation исключены 37 неподдержанных действий исследующей политики и одно неподдержанное продолжение. После фильтрации остались 13 увеличений и 8 уменьшений пула; 4 изменения пула происходили одновременно с уменьшением лимита. Увеличений лимита нет. Этот минимум не покрывает восстановление конкурентности и всё пространство совместных действий.

## Что изменила модель

В лесу 3 узла используют действие над лимитом и 1 — действие над пулом. На 195 train-историях предложения: hold 156, уменьшить лимит 8, увеличить пул 7, одновременно уменьшить лимит / увеличить пул 1; ещё 23 истории требуют baseline. Наличие предложения само по себе не доказывает, что выбор обусловлен Q: в некоторых состояниях поддержка может оставить один вариант.

На validation из 120 историй: hold 86, уменьшить лимит 1, baseline 33. **Изменений пула нет**, хотя поддержанные варианты доступны в 18 историях. При фиксированном действии над лимитом Q различается между действиями пула в 7 сравнимых train-историях и в 0 validation-историй.

Аудит путей объясняет узкую применимость без утверждения причинности: единственный узел `action.pool` (tree 26, node 15) достигается поддержанными кандидатами на 28 train-историях и одной validation-истории. Поддержанные кандидаты по обе стороны его порога доступны в 7 train-историях и в 0 validation-историй. Путь включает прошлые pending, GC, service и timeout; само наличие этих разбиений не доказывает причинную связь. Полные нормированные пороги и счётчики — в `joint-audit.json`.

## Перенос и замкнутый контур

Python JSON-export совпал со sklearn с максимальным расхождением 0.0 на проверенных обучающих входах. С новой моделью выполнены 11 JVM-тестов, включая 81 новую историю: точные float32-признаки, маска, поддержка, выбор и Q с допуском `1e-12`; отдельно 16 sklearn golden inputs. Добавлена самостоятельная регрессия разбиения по признаку действия пула (индекс 209) и округления float32. Сохранены `jvm-fixtures.json`, `jvm-parity.log` и `verification.json`.

[Технический замкнутый прогон](../../raw/balanced-policy-smoke-2026-11-08/README.md) сохранил 90 записей, 54 решения модели и 28 support fallback. Все они совпали с Python. Модель в контуре не меняла пул: 53 удержания и одно уменьшение лимита. Изменения пула относятся к baseline. Следовательно, обученное согласованное управление в контуре по-прежнему не продемонстрировано. Новая модель не заменяет прежний прототип как подтверждённое улучшение.

## Воспроизведение

```bash
python3 docs/benchmark/tools/prepare_dataset.py docs/benchmark/raw/balanced-pilot-2026-11-08 \
  --out /tmp/iasr-balanced-prepared --development-only --validation-scenarios spike
python3 docs/benchmark/tools/train_fqi.py /tmp/iasr-balanced-prepared \
  --development-only --out /tmp/iasr-balanced-model
python3 docs/benchmark/tools/audit_joint_learning.py /tmp/iasr-balanced-prepared \
  --model /tmp/iasr-balanced-model/model.json --out /tmp/iasr-balanced-model-audit.json
python3 docs/benchmark/tools/export_jvm_fixtures.py /tmp/iasr-balanced-model/model.json \
  /tmp/iasr-balanced-prepared /tmp/iasr-balanced-jvm-fixtures.json
mvn --offline -pl iasr-policy -am \
  -Dtest=FqiModelTest,LearnedControllerTest -Dsurefire.failIfNoSpecifiedTests=false \
  -Diasr.test.model=/tmp/iasr-balanced-model/model.json \
  -Diasr.test.fixtures=/tmp/iasr-balanced-jvm-fixtures.json test
```

Для побайтового повторения исходной модели нужен checkout тренера `8972740` и те же зависимости; SHA входов и версии сохранены в артефакте. Последующие дополнения аудитора не меняют сохранённую модель.

Следующий шаг — расширить train с сохранением известных train-траекторий, безопасными увеличениями лимита и более широкими сопоставимыми изменениями пула; проверить задержанные последствия и представление действий. Настройки выбирать на validation, затем провести новую независимую проверку. Уже просмотренный старый test не использовать для настройки и не объявлять окончательным независимым результатом новой итерации.
