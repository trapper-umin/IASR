У обеих политик p95 с восемью воркерами вырос в первых двух блоках и снизился в последних двух. Поблочные разности для AIMD составили +40, +35, −118 и −68 мс. Для FQI они составили +24, +120, −240 и −129 мс. Интервалы изменений при воздействии и их разности включают ноль. Без воркеров goodput FQI был ниже во всех четырёх блоках. Интервал этой разности лишь немного отстоит от нуля и рассчитан без поправки на множественные сравнения.

## Проверка воздействия и регулятора

Во всех восьми эпизодах с воздействием CPU воркеров составил в среднем от 5,99 до 6,85 занятого логического ядра. Трассы покрыли 92,1–98,5% измерения, состав группы воркеров в полных измеренных интервалах не менялся. Средний CPU PostgreSQL составил 1,68–1,75 ядра без воркеров и 2,61–2,69 ядра с ними. Это наблюдаемый расход CPU на обработанную работу. На общем хосте фоновые процессы и изменения доступной вычислительной мощности остаются источниками вариативности.

FQI принимала решения в 75 из 80 полных окон без воркеров и в 77 из 80 с воркерами. Она выполнила соответственно 8 и 6 совместных изменений ресурсов. С учётом прогрева Python воспроизвёл 187 решений модели и 10 fallback по поддержке. Максимальное время inference составило 4,64 мс при бюджете 20 мс.

Воздействие было постоянным от начала прогрева до конца эпизода. Этот протокол меняет конкуренцию за CPU, а фактически доступное приложению CPU определяется планировщиком. Для прямой оценки эффекта ограничения ресурса нужен эксперимент с квотой. В этой серии относительная устойчивость AIMD и FQI осталась неопределённой.
