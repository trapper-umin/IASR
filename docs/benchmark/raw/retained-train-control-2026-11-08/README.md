# Технический контроль выбранной и reference-моделей

Четыре эпизода от 8 ноября 2026 года на чистом `2e0c63d`: steady/selected, steady/reference, spike/reference, spike/selected. Порядок и роли зафиксированы после offline-выбора, до запуска контура в [плане](../../analysis/retained-train-2026-11-08/technical-check-plan.json). `selected` — неизменённый победитель по условной validation Bellman RMSE, **subspace**; reference — заранее включённый контроль, а не новый победитель. [Все модели и результаты выбора](../../models/fqi-retained-train-2026-11-08/README.md) сохранены.

Объект и конфигурация контроллера одинаковы между моделями: 8 воркеров, обслуживание 30 мс, исходный пул 2 (диапазон 2–12), исходный лимит 20, SLO 150 мс, окно 1 с, pool period 5, бюджет inference 20 мс. Режим learned, guardrails и baseline fallback сохранены. По одному повтору на модель/профиль, отдельная JVM, прогрев 6 с, `caffeinate -i`. Полные свойства и порядок — в `execution.json`, фактические настройки и SHA модели — в metadata. Сон хоста блокировался; модель после прогона не переобучалась.

Валидатор проверил **4 эпизода / 179 записей / 142 полных измерительных перехода**, без нерегулярных интервалов. Сохранены четыре конечные записи. Все **160 решений модели** и **3 support fallback** совпали с Python. Желаемые и применённые моделью ресурсы совпали.

## Происхождение действий

| Профиль | Модель | Решений модели | Из них hold | Начальные fallback | Нет поддержки | Среднее / максимум inference, мс |
|---|---|---:|---:|---:|---:|---:|
| steady | selected/subspace | 32 | 32 | 4 | 1 | 0.689 / 6.526 |
| steady | reference | 33 | 33 | 4 | 1 | 0.699 / 7.437 |
| spike | reference | 48 | 48 | 4 | 0 | 0.624 / 7.429 |
| spike | selected/subspace | 47 | 47 | 4 | 1 | 0.623 / 6.494 |

Все изменения лимита и пула выполнил baseline. В том числе три одновременных изменения обоих ресурсов относятся к baseline и не подтверждают обученное согласование. Ошибок модели и превышений кооперативного бюджета не зарегистрировано. Измеренные длительности не являются гарантией реального времени.

На фактических историях у каждой модели было по 17 окон с поддержанным действием над пулом. У reference оба узла `action.pool` **ни разу не достигались** поддержанными кандидатами. Q между сравнимыми действиями пула не различался ни у одной модели. Это уточняет разрыв с offline-результатом reference (6 предложений увеличить пул на validation); само наличие узлов действия и положительных offline-предложений не гарантирует их использование на новой траектории. Это описательная проверка конкретных траекторий, не доказательство единственной причины неудачи.

`comparison.json` сохраняет отдельные счётчики model/fallback, повторное исполнение решений, поддержку и посещение узлов на реальных историях. Аудитор дополнительно проверяет неизменность выбранного кандидата, порядок эпизодов, SHA моделей, чистый общий commit и равенство условий между моделями.

## Проверка

```bash
python3 docs/benchmark/tools/audit_controller_comparison.py \
  docs/benchmark/raw/retained-train-control-2026-11-08 \
  docs/benchmark/models/fqi-retained-train-2026-11-08 \
  --plan docs/benchmark/analysis/retained-train-2026-11-08/technical-check-plan.json \
  --out /tmp/iasr-retained-control-audit.json
```

Новый запуск использует `BenchmarkRunner` по каждому случаю из плана: `bench.modes=learned`, `bench.repeat=1`, соответствующий `bench.scenarios`, `bench.allowPrototype=true`, SHA-проверенный `bench.model` и свойства из плана. Каждая JVM пишет отдельный каталог. В сохранённом запуске classpath брался из текущих reactor-классов и `iasr-benchmark/target/surefire-reports/TEST-*.xml`; Maven-альтернатива описана в [инструкции JVM](../../../dissertation/jvm-policy.md).
