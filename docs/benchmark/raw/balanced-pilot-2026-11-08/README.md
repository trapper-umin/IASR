# Пилот сбалансированного сбора

9 эпизодов / 427 записей от 8 ноября 2026 года. Исходники приложения и заранее зафиксированный [протокол](../../../dissertation/joint-data-iteration.md) — `980ab8e`, рабочее дерево было чистым при старте. Политика `explore-balanced`, epsilon 1, policy seed 20261109, order seed 42; по три полных повтора `steady`, `ramp`, `spike`. Процесс запускался через `caffeinate -i java --class-path` с текущими reactor-классами после `clean verify`.

Синтетический объект: 8 воркеров, 30 мс обслуживания, исходный пул 2, диапазон пула 2–12, исходный лимит 20, SLO 150 мс, окно 1 с и pool period 5. Прочие параметры стандартные и сохранены в metadata. Счётчики балансировки сбрасываются при каждом эпизоде; seed эпизода формируется из базового seed, профиля и номера повтора. Это исследующая политика; её нагрузочные показатели не являются результатами обученной модели.

Подготовка даёт 195 train-примеров (все steady/ramp) и 120 validation-примеров (все spike). В пилоте **нет test**. Разделение фиксируется профилем и сохраняет все повторы вместе. Старые test-эпизоды в подготовку и обучение этого пилота не входят.

После фильтра поддержки осталось 166 train-переходов: 78 удержаний, 67 уменьшений лимита, 9 увеличений только пула, 8 уменьшений только пула и 4 одновременных уменьшения лимита / увеличения пула. Три прохода: 195 → 169 → 166 → 166. Совместные изменения впервые сохраняются в реально обучающей выборке; это только необходимый минимум покрытия. Увеличений лимита и совместных уменьшений обоих ресурсов после фильтра нет. Пилот недостаточен для проверки восстановления лимита и полного пространства совместных действий.

Сохранены полные эпизоды, журнал, валидация, manifest, покрытие и аудит фильтрации. Подготовленные истории восстанавливаются командами:

```bash
python3 docs/benchmark/tools/validate_episodes.py docs/benchmark/raw/balanced-pilot-2026-11-08
python3 docs/benchmark/tools/prepare_dataset.py docs/benchmark/raw/balanced-pilot-2026-11-08 \
  --out /tmp/iasr-balanced-prepared --development-only --validation-scenarios spike
python3 docs/benchmark/tools/audit_joint_learning.py /tmp/iasr-balanced-prepared \
  --out /tmp/iasr-balanced-audit.json
python3 docs/benchmark/tools/train_fqi.py /tmp/iasr-balanced-prepared \
  --development-only --out /tmp/iasr-balanced-model
```

Фиксированные параметры первой попытки: 8 итераций, 32 дерева, глубина 6, leaf 3, seed 42, gamma 0.95; поддержка 3 примера / 2 эпизода / RMS 2.0. Модель сохраняет `deploymentAllowed: false`, а test помечается как неоценённый. Условная Bellman-ошибка не является оценкой качества политики. Нужны расширение train с безопасными увеличениями лимита, новые независимые эпизоды и сравнение с абляциями.
