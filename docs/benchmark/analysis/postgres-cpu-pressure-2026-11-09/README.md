# Контролируемая конкуренция за CPU

## Протокол до запуска

Первая проверка устойчивости сравнивает AIMD и замороженную полную FQI при 0 и 8 конкурирующих CPU-воркерах. Выбрана одна новая конфигурация PostgreSQL. Данные прежних отложенных серий и выборка обучения сохраняют отдельные роли. Проверка относится к двум регуляторам и одной дозе CPU-нагрузки.

- `steady` подаёт 72 запроса/с в течение 21 с после штатного прогрева 6 с. Запрос использует 320 000 строк. Начальный лимит 10, пул 12 с границами 2–16, SLO 150 мс. Модель, бюджет inference и правила контроллера совпадают с предыдущими сериями.
- В каждом из четырёх блоков четыре комбинации политики и числа воркеров. Каждая комбинация один раз занимает каждую позицию и один раз непосредственно следует за каждой другой комбинацией в пределах блоков. Каждый эпизод запускается в собственной JVM и временном кластере PostgreSQL 17.10.
- При воздействии восемь отдельных процессов непрерывно вычисляют PBKDF2 в памяти. Они готовы до запуска JVM и останавливаются перед остановкой временной СУБД. Эта нагрузка конкурирует за планирование на общем хосте. Степень сокращения доступного ресурса зависит от планировщика и прочей нагрузки.
- Секундные снимки накопленного CPU-времени разделяют JVM, PostgreSQL и воркеры. Требуется минимум 80% покрытия фазы. Доза считается достигнутой при среднем CPU воркеров от 5 логических ядер и сохранении процессов в измеренных интервалах. Если доза ниже, исходы сохраняются и отчёт помечает ограничение. Фоновая загрузка прочих процессов отдельно не измеряется.
- Основные метрики — goodput и клиентский p95. Дополнительно сохраняются p99, нарушения SLO, 429, жёсткие отказы и действия регулятора. Для каждой политики рассчитывается парная разность «8 воркеров минус 0». Сравнение FQI с AIMD выполняется при каждой дозе. Устойчивость политик сравнивается по разности изменений при воздействии. Все интервалы Стьюдента по четырём блокам описательные и без поправки на множественные сравнения.

[Порядок, SHA и пороги](protocol.json) зафиксированы до запуска.

[Результаты и исходные трассы](../../raw/postgres-cpu-pressure-2026-11-09/README.md) сохранены после завершения всех блоков.

## Воспроизведение

Из чистого checkout с JDK 17, PostgreSQL 17.10 и [зависимостями анализа](../../tools/requirements-ml.txt) соберите стенд командой `mvn --offline clean verify`. Для эксперимента нужен общий POSIX-хост и доступ к `ps`. Восемь воркеров занимают CPU только во время эпизодов воздействия.

```bash
study=docs/benchmark/analysis/postgres-cpu-pressure-2026-11-09/protocol.json
python3 docs/benchmark/tools/cpu_pressure_study.py "$study" /tmp/iasr-pressure
python3 docs/benchmark/tools/cpu_pressure_study.py "$study" /tmp/iasr-pressure \
  --audit-out /tmp/iasr-pressure-analysis.json
```
