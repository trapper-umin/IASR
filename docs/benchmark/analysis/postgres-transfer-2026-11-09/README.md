# Первая серия PostgreSQL для этапа 5

Замороженная per-action модель проверяется на локальном PostgreSQL 17.10. Источники обучения этой модели содержат синтетическую зависимость. В новой серии используется запрос `sum(i) from generate_series(1, N)` в отдельном кластере на том же хосте, что и JVM. Сценарий slow-dependency уже применялся с синтетической зависимостью. Здесь новые условия включают СУБД, стоимость запроса, нагрузку и начальный пул.

Калибровка до запуска режимов использовала 500 000 строк и 1,5 с на уровень. Четыре соединения дали 90,0 rps при среднем времени запроса 43,6 мс. Это ориентир для выбора условий. При 75 rps базовая стоимость составляет 500 000 строк. С 15-й по 35-ю секунду стоимость возрастает до 1 000 000 строк. Обозначения 25 и 50 мс в конфигурации задают множитель числа строк. Измеренное время запроса зависит от конкуренции за CPU.

Режимы fixed, adaptive (штатный AIMD с регулированием пула), Gradient и learned проходят по четыре повтора в одном процессе стенда. Каждый повтор поднимает отдельный контекст приложения. Seed 20261109 фиксирует начальную перестановку. В следующих повторах порядок циклически сдвигается, и каждый режим занимает каждую позицию один раз. Стартовый лимит 20, пул 4, диапазон пула 2–12, SLO 150 мс. Контур работает с окнами по 1 с, с обычным прогревом 6 с. Значения и SHA модели зафиксированы в `protocol.json`.

Основные показатели серии — goodput и клиентский p95 успешных ответов. Показываются также p99, доля успешных запросов вне SLO, 429 и жёсткие отказы. Для каждого режима приводятся различия с AIMD в пределах одного повтора. Интервалы Стьюдента по четырём парным разностям описательные и без поправки на множественные сравнения. Они опираются на предположение о независимых примерно нормальных разностях. Общий хост и последовательные блоки ограничивают это предположение.

Восстановление после 35-й секунды определяется как время до конца третьего подряд полного окна с серверным p95 ≤ 150 мс и goodput ≥ 67,5 rps. При отсутствии такого отрезка время помечается как цензурированное. Изменения ресурсов и fallback считаются отдельно. План и модель фиксируются до замеров. Одна конфигурация PostgreSQL оставляет открытыми проверку на других объектах и абляции координации.
