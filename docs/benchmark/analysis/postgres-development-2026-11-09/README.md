# Сбор траекторий разработки на PostgreSQL

Первый тест переноса показал, что эмпирическая поддержка ограничивает работу модели. В 136 окнах с fallback 124 раза ни одно разрешённое действие не имело минимального покрытия в группе состояния. Самая частая группа сочетала задержку выше SLO, занятый лимит допуска, отсутствие ожидания соединения и такт изменения лимита. Новый сбор проверяет, даёт ли отдельная выборка PostgreSQL больше поддержанных действий в состояниях, характерных для этой зависимости.

## План до запуска

- Выполнить по четыре эпизода `slow-dependency`, `ramp` и `spike` на временном PostgreSQL. Первые два профиля полностью относятся к train, `spike` целиком к validation. Все эпизоды исходной серии сравнения зарезервированы для оценки и не передаются подготовке, обучению или валидации.
- Использовать отдельные условия. Лимит начинается с 8, пул с 4 при границах 2–12. Запрос использует 400 000 строк, в деградации 900 000. Номинальные интенсивности составляют 90 rps для `slow-dependency`, 36–300 rps для `ramp` и 72/240 rps для `spike`. Это настройки генератора, фактическая пропускная способность определяется измерениями. Прежняя короткая калибровка используется как ориентир.
- Собирать данные штатным `explore-balanced` с epsilon 0,75 и обычными guardrails. В окнах без исследования выбирается удержание. Политика исследования может менять пул на каждом пятом такте при наличии допустимых действий. В отчёте используются фактически применённые действия, окна измерения и полные истории.
- Сохранить 455 прежних синтетических train-переходов и расширить их новой частью PostgreSQL. Validation содержит только новый профиль `spike`. Первую попытку per-action FQI выполнить с прежними параметрами и порогами поддержки. При недостатке совместного покрытия после фильтра обучение прекращается без экспорта. Замороженная модель нужна как контроль в offline-аудите. В сборе она не принимает решений.
- На одних и тех же историях PostgreSQL validation сравнить долю историй с хотя бы одним допустимым поддержанным действием, с поддержкой фактического действия и с возможностью изменить пул или оба ресурса. Показать результаты по группам состояний и эпизодам. Эти метрики описывают покрытие на траекториях исследующего регулятора. Эффективность и перенос новой политики проверяются позже на свежих условиях.

Параметры, seeds и идентификатор зарезервированной группы зафиксированы в [протоколе](protocol.json). Сбор запускается существующим `run_postgres_transfer.py` из чистого checkout. Серия сравнения и её модель остаются в архиве.

## Воспроизведение

Из корня чистого checkout с зависимостями [стенда PostgreSQL](../postgres-transfer-2026-11-09/README.md) выполните сбор и восстановите замороженные входы исходной модели. Скрипт обучения сверяет SHA прежнего train и его манифеста, переносит только train и сохраняет новую validation побайтово.

```bash
protocol=docs/benchmark/analysis/postgres-development-2026-11-09/protocol.json
python3 docs/benchmark/tools/run_postgres_transfer.py "$protocol" \
  --out /tmp/iasr-postgres-development
python3 docs/benchmark/tools/prepare_dataset.py docs/benchmark/raw/balanced-pilot-2026-11-08 \
  --out /tmp/iasr-prior-balanced --development-only --validation-scenarios spike
python3 docs/benchmark/tools/extend_development_dataset.py \
  docs/benchmark/raw/fqi-prototype-2026-11-08/preparation-manifest.json \
  /tmp/iasr-prior-balanced \
  --prior-raw docs/benchmark/raw/fqi-prototype-2026-11-08 \
  --out /tmp/iasr-prior-retained
python3 docs/benchmark/tools/develop_postgres_policy.py \
  /tmp/iasr-postgres-development "$protocol" /tmp/iasr-prior-retained \
  --out /tmp/iasr-postgres-fqi
```

Для воспроизведения обучения на уже собранных траекториях подставьте архивный каталог вместо `/tmp/iasr-postgres-development`. Повторный живой сбор получает собственные временные метки и измерения.

## Результат

Сохранены [все 12 эпизодов](../../raw/postgres-development-2026-11-09/README.md). Из 319 новых переходов train после согласования поддержки осталось 302. Смешанный train содержит 774 перехода, из них для обучения пригодны 726. Все 160 историй validation принадлежат профилю `spike` PostgreSQL. Зарезервированная группа отсутствует среди входов новой модели.

| Поддержка на одних и тех же историях validation | Только синтетический train | Синтетика и PostgreSQL |
|---|---:|---:|
| Хотя бы одно допустимое действие | 5/160 | 157/160 |
| Фактически применённое действие | 5/160 | 157/160 |
| Изменение пула, где оно допустимо | 0/32 | 29/32 |
| Совместное изменение, где оно допустимо | 0/1 | 0/1 |
| Хотя бы одно действие в самой частой группе fallback | 0/114 | 114/114 |

Изменение покрытия отражает расширение train и повторное построение преобразований и поддержки. Условия validation принадлежат одному профилю и четырём эпизодам исследующего регулятора. Покрытие на этих траекториях не даёт оценки goodput, задержки или решений в замкнутом контуре.

На новом PostgreSQL train совместное изменение было допустимо в 9 из 319 переходов и применилось однажды. На 51 из 64 тактов изменения пула лимит уже находился на минимуме, а p95 превышал SLO. В этих состояниях маска запрещала и уменьшение, и увеличение лимита. Ещё в четырёх тактах совместное изменение блокировал cooldown лимита. Единственный применённый совместный переход не пережил фильтр. Все десять совместных переходов, использованных смешанной моделью, пришли из прежнего синтетического train. Сбор расширил поддержку состояний и действий над отдельными ресурсами. Для совместных действий нужен отдельный сбор с достаточным числом окон, где оба изменения допустимы.

[Сравнение поддержки](support-comparison.json) содержит разбиение по группам и эпизодам. [Аудит train](joint-audit.json), [покрытие PostgreSQL](postgres-coverage.json) и [манифест подготовки](preparation-manifest.json) фиксируют фильтрацию и границы разделов. [Новая модель](../../models/fqi-postgres-development-2026-11-09/README.md) и отчёты повторились побайтово на `130f99a`. Прошли 57 Python-тестов и 13 JVM-тестов на 69 историях.

После offline-аудита по [отдельному протоколу](live-smoke-protocol.json) выполнен [одиночный технический запуск](../../raw/postgres-development-smoke-2026-11-09/README.md) на знакомом профиле `spike`. В 44 полных окнах новая модель приняла 43 решения, изменила лимит 12 раз и пул 5 раз, включая одно совместное изменение. Python воспроизвёл все решения модели. Этот эпизод предназначен для проверки подключения.
